# 技术文档

## 1. 总体架构

系统采用发布/订阅模型，由六个模块组成：

- Message：消息类，封装消息内容，构造时自动生成时间戳
- Node：节点抽象基类，持有节点名，声明纯虚函数 init() 与 shutdown()
- Publisher：发布者节点，继承 Node，publish() 将消息交由 RosCore 转发
- Subscriber：订阅者节点，继承 Node，onMessage() 接收并打印消息
- RosCore：核心管理单例，负责节点注册、维护话题与订阅者的映射关系、转发消息、统一关闭节点
- Exceptions：自定义异常类，针对节点、话题、消息三类非法操作分别定义异常

## 2. 关键技术点

### 2.1 继承与多态

Node 是抽象基类，init() 与 shutdown() 声明为纯虚函数（= 0），强制子类实现各自逻辑。Publisher 与 Subscriber 重写（override）这两个函数，析构函数声明为 virtual，保证通过基类指针释放子类对象时析构正确。

消息转发时，RosCore 持有的是 Node* / Subscriber* 基类指针，通过基类指针调用 onMessage() 与 shutdown()，实际执行的是子类版本——这是多态的核心应用。

### 2.2 单例模式

RosCore 构造函数私有化，静态成员 instance 初始为 nullptr。getInstance() 首次调用时创建唯一实例，之后所有调用返回同一实例，保证全局只有一份映射表。

### 2.3 数据结构选择

- map<string, vector<Subscriber*>>：维护"话题 → 订阅者列表"的映射，支持一个话题对应多个订阅者；map 按话题名自动排序，查找效率为 O(log n)
- vector<Node*>：记录所有已注册节点，用于 shutdownAll() 统一关闭

### 2.4 异常处理

按非法操作的类别定义三个异常类，均继承标准库的 std::runtime_error：

| 异常类 | 触发条件 | 抛出位置 |
|--------|----------|----------|
| NodeException | 节点名为空 | Node 构造函数 |
| NodeException | 重复节点注册 | RosCore::registerNode |
| MessageException | 发布空消息 | RosCore::sendMessage |
| TopicException | 向不存在的话题转发消息 | RosCore::sendMessage |

校验全部放在系统入口处（构造函数、注册函数、发送函数），非法数据无法进入系统内部。sendMessage 中判断话题是否存在使用 map 的 find 方法而非下标访问，避免为不存在的话题凭空创建空记录。

main.cpp 中对每个异常场景使用 try/catch 捕获，捕获后打印 e.what() 中的错误信息，程序继续运行，满足"程序禁止崩溃"的要求。

### 2.5 分级日志与持久化

Logger 类提供统一的日志出口，按严重程度分为三级：

| 级别 | 用途 | 本系统中的示例 |
|------|------|----------------|
| INFO | 正常流程信息 | 节点初始化、消息转发、节点关闭 |
| WARN | 不影响运行但值得注意的情况 | 移除不存在的节点、关闭时无已注册节点 |
| ERROR | 非法操作导致的异常 | 空节点名、重复注册、空消息、不存在话题 |

每条日志的格式为"[级别] [时间] [模块] 内容"，通过 Logger::setFile 设置日志文件路径后，日志在输出到控制台的同时追加写入 ros_log.txt，实现日志持久化，便于运行后复查。

### 2.6 自定义消息类型

Message 的 getContent() 声明为 virtual，消息类型可扩展。TempHumidityMessage 继承 Message，额外保存温度、湿度两个数值，并重写 getContent() 将数值拼装为可读字符串。

转发链路相应提供消息对象版本的重载：Publisher::publish(const Message&) 与 RosCore::sendMessage(const string&, const Message&)。自定义消息对象沿原链路转发时保留实际类型，订阅者 onMessage 中调用 getContent() 时按对象实际类型执行（多态），收到的是温湿度格式的内容。文本消息与自定义消息共用同一条链路。

### 2.7 动态增删节点

RosCore 提供 removeNode(Node*) 与 unregisterSubscriber(topic, Subscriber*)，支持在运行中途移除节点：removeNode 将节点从统一管理名单中移除，unregisterSubscriber 将订阅者从话题映射表中移除。移除后该节点不再收到后续消息，实现节点拓扑的动态调整；节点加入则通过既有的 init()/registerNode/registerSubscriber 流程完成。

### 2.8 编译配置

源文件采用 UTF-8 编码，编译时加入 -fexec-charset=GBK，使程序输出的中文在 Windows 控制台正常显示；-std=c++11 保证 auto、nullptr 等特性可用。

## 3. 程序运行流程

1. 创建发布者与订阅者对象
2. 各节点 init()：输出 INFO 级初始化日志，向 RosCore 注册节点；订阅者同时登记到对应话题的订阅者列表
3. 发布者 publish()：RosCore 校验消息与话题合法性，将内容包装为 Message（自动生成时间戳），遍历该话题的订阅者列表，逐个调用 onMessage() 转发；自定义消息对象走重载版本，保留实际类型转发
4. 动态节点演示：运行中途注册新订阅者（可收到后续消息），再移除该节点（不再收到后续消息）
5. main 函数中依次演示四种异常场景，每个场景由 try/catch 保护，异常被捕获后以 ERROR 级日志输出错误信息
6. shutdownAll()：遍历所有节点，通过基类指针调用 shutdown() 统一关闭
