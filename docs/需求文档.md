# 需求文档 —— C++ 模拟 ROS 发布/订阅通信系统

## 1. 项目背景

ROS（Robot Operating System）是机器人开发中广泛使用的软件框架，其核心通信机制之一是
"发布/订阅"（Publish/Subscribe）模型：消息的发送方（发布者）与接收方（订阅者）不直接通信，
而是通过 ROS 核心按"话题"（Topic）进行消息转发。发布者向某个话题发布消息，
所有订阅了该话题的订阅者都会收到这条消息。这种机制使各功能模块之间实现解耦，
可以独立开发、独立测试。

本项目要求用 C++ 语言对上述机制进行简化模拟，实现一个 mini ROS 系统，
重点练习面向对象设计（封装、继承、多态）、单例模式以及异常处理。

## 2. 功能需求

### 2.1 Message 消息类
- 封装一条消息，包含：字符串内容、发送时间戳
- 时间戳格式为 YYYY-MM-DD HH:MM:SS，在消息对象构造时自动生成
- 消息内容创建后不可修改，对外只提供只读访问接口（get 函数），保证封装性

### 2.2 Node 节点抽象基类
- 每个节点拥有唯一名称，名称不允许为空
- 定义统一的接口：init()（初始化节点）、shutdown()（关闭节点）
- 由具体子类实现这两个接口，Node 本身不直接实例化

### 2.3 Publisher 发布者
- 继承自 Node，绑定一个话题名称
- init() 时向 ROS 核心注册，shutdown() 时输出关闭日志
- 提供 publish() 接口：将字符串内容包装为 Message 对象，交给 ROS 核心转发

### 2.4 Subscriber 订阅者
- 继承自 Node，绑定一个话题名称
- init() 时向 ROS 核心注册并订阅话题，shutdown() 时输出关闭日志
- 收到消息后执行回调函数，打印消息内容与时间戳

### 2.5 ROS 核心管理模块（单例）
- 全局唯一实例，采用单例模式实现
- 维护"话题 → 订阅者列表"的映射关系，一个话题可对应多个订阅者
- 提供消息转发：收到某话题的消息后，推送给该话题下的全部订阅者
- 提供 shutdown()：遍历并统一关闭所有已注册节点

### 2.6 异常处理要求
以下异常场景必须被正确处理：抛出异常并给出语义清晰的错误提示，不允许程序崩溃。
- 节点名称为空
- 节点重复注册
- 发布的消息内容为空
- 向不存在的话题发布消息

### 2.7 可选扩展（加分项）
- 自定义消息类型（如温湿度传感器数据）
- 日志分级（INFO / WARN / ERROR）及日志持久化到文件
- 支持运行时动态添加、移除节点

## 3. 验收标准

1. 一个发布者向话题发送消息后，该话题下的所有订阅者均能收到并正确打印消息内容与时间戳
2. 更换消息内容、增加订阅者数量后，转发结果依然正确
3. 时间戳格式符合 YYYY-MM-DD HH:MM:SS，且与消息发送时间一致
4. 第 2.6 节列出的异常场景均不导致程序崩溃，且错误提示信息明确
5. ROS 核心 shutdown() 后，所有节点均被正确关闭并输出关闭日志
